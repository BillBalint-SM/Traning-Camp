# Multimodal and Collaboration Knowledge v5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expand the portable Hungarian agent knowledge package from 155 to 193 source-neutral modules with real-time multimodal and multi-agent coordination guidance.

**Architecture:** Add `real-time-multimodal` and `multi-agent-coordination` as new L1 areas while preserving the existing general interaction routes. The first area owns voice, GUI, latency, embodied control, and simulation transfer; the second owns collaboration classification, context boundaries, topology, communication, failure containment, and society-scale simulation. Derived indexes, graph, and manifest remain forge-generated; semantic review evidence remains private and ignored.

## Acceptance Criteria

- Exactly 193 valid modules, six exact new routes, resolved graph endpoints, and all indexes at or below 8192 bytes.
- Eighteen multimodal modules and twenty coordination modules are assigned exactly once.
- Public `pack/` contains no origin, author, publication, acquisition, URL, private ID, or workspace reference.
- All 38 promotions resolve to reviewed private units; private artifacts stay ignored.
- Package verification, two identical archives, full pytest, Ruff, diff/scope review, and staged public-boundary scan pass.
- The dev slice is pushed, fast-forwarded into `feature`, reverified, archived across environments, and its merged worktree is removed.

## Scope and Risks

- In scope: voice architecture, streaming and duplex interaction, fast/slow boundaries, GUI action space, multisensory grounding, latency, embodied planning/control, sim-to-real, multi-agent context/topology, communication, filesystem coordination, failure containment, and society/economy simulations.
- Out of scope: controlling a real device, installing browser/robot frameworks, cloning external repositories, provider integration, or changing a consuming platform.
- Risks: alias overlap with the existing interaction area, advice that confuses simulation with real-world evidence, concurrency guidance without ownership, and index-budget growth.

## Verification Strategy

- Observe focused RED routing tests before the areas and modules exist.
- Generate all derived package artifacts only with `knowledge-forge build-package`.
- Validate exact routes, old-route compatibility, graph, membership, budgets, neutrality, private endpoints, deterministic archives, full tests, lint, staged scope, and merged-feature behavior.
